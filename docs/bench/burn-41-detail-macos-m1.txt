BURN-41 first-detail-run bench in the real Aria Burn webview: macOS 14.6.1, WKWebView ("Apple GPU"),
Apple M1, on AC power, run 2026-11-04. NOT Windows/Iris Xe.
Branch burn-41 at a801505, served with `npx vite bench --port 5241 --strictPort`. The app was aria-burn
target/debug/aria-burn with ARIA_BURN_BENCH_URL='http://localhost:5241/?auto=detail'; reports came back over
POST /__bench-report. Foreground native window (page visible). WKWebView's performance.now() has 1 ms
resolution. Each attempt waited for 30 s with no vitest / cargo / rustc / tsc process and was to be discarded
if one appeared during the run; none did, so all three were kept (16:55, 16:56, 16:57).

What the scenarios are (bench/bench.ts runDetailBench, ?auto=detail):
- app sequence: what aria-burn's tick does: GlSim.fit, the full run, then the first runDetail over a
  1920 × 1080-cell view at the 5 µm detail pitch, then pans. On this M1 both budgets plan 2 × 2 tiles, so fit
  already built the whole-job bins and the detail run used them (as before BURN-41).
- after releaseTargets: the BURN-37 bench's sequence (the one that measured 2.4–2.6 s on Iris Xe):
  releaseTargets between the full run and the detail run. That drops the bins and the thermal step's GPU
  state, so the detail run re-uploads the per-sample thermal energies (19.7 M samples, ~157 MB) and now
  bins only a window of buckets around the view.
- before BURN-41: the same sequence with the whole-job bins built in the detail run, as runDetail did
  before; split into thermal re-upload, whole-job bins and the run.

Summary (3 kept runs, min–max):

                                         default budget (256 M, k = 2)   Iris Xe budget (50 M, k = 3)
  app sequence, first detail             15–18 ms                        12–15 ms
  after releaseTargets, first detail     449–461 ms                      414–426 ms
  before BURN-41, same sequence          822–930 ms                      617–692 ms
    of which whole-job bins              420–535 ms                      247–324 ms
    of which thermal re-upload           245–253 ms                      238–248 ms
  pans ×5 (37 cells), median             12–13 ms                        10–12 ms
  far pans ×3 (1920 cells), median       11–13 ms                        10–11 ms

- Window bins cut the binning part of the first detail run from 250–535 ms to roughly 20–80 ms here (the
  after-releaseTargets time minus the thermal re-upload and the run).
- What is left on the BURN-37 bench sequence is mostly the thermal re-upload. The app does not pay it in a
  detail run: GlSim.fit uploads the thermal state before the full run, and releaseTargets only runs when a
  job is closed or cleared.
- Window bins vs whole-job bins, GPU readback of fluence/dose, colour, depth and verdict over three views and
  two cutoffs: bit-identical in every run.
